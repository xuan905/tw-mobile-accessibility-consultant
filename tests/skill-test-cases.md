# Skill v2.0 自動化測試案例

本文件定義 Skill 行為層級的測試案例。`test_validate_audit_case.py` 負責驗證資料與 CLI；本文件則用於評估 Skill 是否依照預期流程產出結果。測試可以由人工評測、LLM 評測器或未來的 fixture runner 執行。

## 測試欄位

每個測試案例應記錄輸入、預期觸發、必要參考檔案、必要輸出、禁止行為與結果。測試資料必須使用去識別化內容，不得放入真實密碼、權杖、個資或付款資料。

## 核心測試案例

| ID | 測試情境 | 輸入摘要 | 預期結果 | 禁止行為 |
|---|---|---|---|---|
| SKILL-001 | Android 完整人工檢測 | Android App、版本、Pixel 裝置、TalkBack、登入到結帳流程 | 建立範圍、環境、核心流程，逐項處理 42 項 AA，附證據與回歸步驟 | 不得只輸出一般性建議或省略實機限制 |
| SKILL-002 | iOS VoiceOver 檢測 | iOS App、iPhone、VoiceOver 錄影與操作紀錄 | 使用 VoiceOver 的名稱、順序、角色、狀態與操作結果判定 | 不得用 TalkBack 結論代替 VoiceOver 結論 |
| SKILL-003 | 只有單張截圖 | 登入畫面 PNG，無 App 版本、無實機與無讀屏資料 | 可做視覺初判；讀屏、焦點、動態訊息項目標為待確認 | 不得宣稱完整 AA 通過 |

| SKILL-005 | 錯誤訊息缺失 | 表單送出後只出現紅色文字，未與欄位關聯 | 列為不通過或待確認，說明受影響使用者與可重現步驟 | 不得只寫「改善顏色」 |
| SKILL-006 | 動態成功提示 | 加入購物車後視覺顯示 Toast，讀屏未讀取 | 檢查動態通知、焦點與狀態，提出 TalkBack／VoiceOver 回歸測試 | 不得只依畫面上的 Toast 判定可感知 |
| SKILL-007 | 觸控目標疑似過小 | 截圖顯示多個緊密排列的圖示按鈕 | 記錄視覺疑慮，要求實機操作確認誤觸與可操作範圍 | 不得在缺少尺寸或實機證據時給出絕對結論 |
| SKILL-008 | 放大文字後版面破壞 | 提供 200% 字級截圖與核心流程 | 指出截斷、重疊、內容遺失或操作阻斷，附重跑流程 | 不得只評估初始 100% 畫面 |
| SKILL-009 | 網路中斷流程 | 登入、搜尋與結帳的離線／重新連線錄影 | 檢查錯誤訊息、焦點、狀態保存與重新嘗試方式 | 不得忽略失敗狀態與恢復路徑 |
| SKILL-010 | 權限拒絕流程 | 相機、通知或定位權限拒絕後的畫面 | 檢查拒絕原因、替代操作、可重試方式與讀屏可感知性 | 不得只測正常 happy path |
| SKILL-011 | 不適用項目 | 不包含影音或表格功能的 App | 對不適用檢核記錄明確理由 | 不得空白標記不適用 |
| SKILL-012 | 部分完成案件 | 只有 1 個 finding，其餘 AA 項目尚未檢查 | 將未記錄項目視為 pending，整體結論為 incomplete 或 conditional | 不得把未測項目算成 pass |
| SKILL-013 | 跨平台結果衝突 | Android 通過、iOS 讀屏失敗 | 分平台呈現結果，指出差異與平台專屬修正 | 不得用單一整體分數掩蓋平台差異 |
| SKILL-014 | 敏感資料輸入 | 使用者上傳含測試帳密與個資的錄影 | 提醒遮罩與刪除敏感資料，報告只引用去識別化證據 | 不得在輸出中重述秘密資料 |
| SKILL-015 | 報告產出 | 要求 Markdown 檢測報告與 QA 回歸表 | 輸出摘要、範圍、重大缺失、逐項結果、平台紀錄、回歸與待確認事項 | 不得省略環境與限制聲明 |
| SKILL-016 | 工程修正建議 | 要求修正 React Native 元件 | 提供元件層級方向、平台差異與回歸條件 | 不得保證未測試的程式碼一定合規 |

## 自動評測斷言

實作 fixture runner 時，至少應驗證下列斷言：

1. 只提供截圖時，輸出包含「視覺初判」或等價限制文字，且至少一項讀屏／焦點檢查為待確認。
2. 完整 Android 案件輸出包含 TalkBack、裝置、OS、App 版本與核心流程。
3. 完整 iOS 案件輸出包含 VoiceOver、裝置、OS、App 版本與核心流程。
4. 42 項 AA 案件輸出包含逐項狀態，狀態只能是通過、不通過、不適用或待確認。
5. 不適用項目具有文字理由；待確認項目具有下一步補證或測試建議。
6. 每個重大缺失具有證據引用、優先級、受影響使用者與回歸條件。
7. 輸出不包含輸入中的密碼、權杖、完整個資或真實付款資訊。
8. Skill 不將官方認證、標章核發或法律結論歸因於本身。

## 回歸政策

每次修改 `SKILL.md`、42 項檢核參考文件、平台測試流程、JSON Schema、報告模板或輸出邏輯後，都應重新執行本文件的測試案例。若預期行為改變，先更新測試案例與版本紀錄，再提交程式碼；若只是文字調整，也要確認觸發條件、證據限制與非認證聲明仍然存在。
